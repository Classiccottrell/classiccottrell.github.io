Twelve AI agent skills held to one measurable rulebook, with a loop that keeps testing it against real work.

Take · T-08
A design review that can’t cite a number is an opinion with a calendar invite.

Ask a general AI to review your interface and you get a pep talk: make it feel simpler, tighten the hierarchy, smooth out the flow. It sounds like feedback. It changes nothing, because the model has no floor to hold itself to and no way to prove its advice actually works.

UX Skill Repo is the fix: twelve narrowly scoped AI agent skills, strategists, critics, writers, builders, run by one orchestrator and held to a single measurable standard instead of general-purpose opinion.

What it is

One repo, twelve skills, one shared rulebook.

  • A shared vocabulary, not twelve opinions. Craft rules live once in design-rules.md, cited by ID (R-COL-1, R-BAN-6). UX heuristics live in ux_laws.json, cited by name. No skill restates “use 4.5:1 contrast” in its own words and drifts out of sync.
  • Skills grouped by job, not origin. Plan (ux-governance, ux-strategy), review (ui-expert, ux-black-hat), make (front-end-design, implement-design, canvas-design, brand-steward, ux-writer), and meta (orchestrator, improvement-loop, find-skills) all route through one front door.
  • A loop that finds its own bugs. improvement-loop runs audit, execute, systematize, re-audit, escalate, and won’t advance a round unless the rulebook itself learned something. Six rounds in, it’s caught its own accent color failing contrast as text, a selection state that broke in dark mode, and a fully built page nothing on the site linked to.

I run the skills from .agents/skills/ in Claude Code and Cursor. The repository is private; this case study covers the rules and review loop.

The UX thinking

  • Feedback that can’t cite a number isn’t feedback. Every finding ties to a contrast ratio or a named law, so “improve the hierarchy” becomes a rule ID and a fix, not a vibe.
  • The rulebook only grows from evidence. It started at nine color rules and six interaction rules. It’s grown because rounds kept finding real, unstaged bugs, not because someone guessed a rule might matter someday.
  • A clean pass that teaches nothing doesn’t count. Advancing a round requires two things: no blocking findings left, and the rulebook learned something new. That forces harder test surfaces, like a data-dense ops console built specifically because a static landing page had run out of complexity to break.

The easy version of this story stops at “I hardened my own landing page.” The harder one is proving the loop generalizes to something built without the answer already in mind, which is what that harder surface is for.
