Take · T-04
An accessibility report nobody can find is a liability with a cover page.

I built VPAT Vault to make a VPAT simple enough that more websites can publish one. The prompt toolkit and a free Chrome scanner are live and for sale. The command-line scanner I'm building now is early and not released, and it takes the same idea from one page to a whole site.

Why I made it

A VPAT is a table of claims, and every row needs evidence behind it. I wanted the scan, the bug list and the draft to sit in one chain, so the evidence follows the work instead of ending up in a separate folder. The last link is always a person: ITI labels only, Supports only when there are no known defects, and every defect remark says what fails, who is affected and where.

What is live: nine prompts with explicit output contracts, a validator with no dependencies, a 50-record reference dataset, a fixed HTML report template that checks its fields and ITI labels before it renders, and a deterministic ZIP for the buyer. The free Chrome extension, VPAT Vault Scanner, runs axe-core on the active tab, on your machine, and exports normalized findings plus manual-review items as JSON. You can install it locally today; a Chrome Web Store listing comes later.

What I'm building is wcag-toolkit, a command-line scanner at v0.1 that is not released. It scans one page, a whole site, or pages behind a sign-in using a browser session you save yourself. The site scan follows links from a start page, opens addresses only, never clicks, skips risky links and reads a sitemap. A static scan of a codebase or a git diff looks for what axe can't see: missing alt text, non-native interactive elements, ARIA misuse, contrast tricks.

Results go into a bug sheet in Markdown, CSV or JSON, one row per defect with its WCAG criterion, severity, confidence and a default disposition. From that sheet the tool scaffolds a VPAT draft, and the draft is capped at Partially Supports, because scan data alone can't say Supports or Does Not Support. A settle delay, redirect and CSP guards and checkpointing mean a page that failed to load never gets reported as zero violations. Type wcag for a guided terminal menu; there is also a thin Claude Code skill and a short how-to micro site.

The limits, plainly: I've tested signed-in scanning only on a practice page, a scan finds some problems and a person tests the rest, and I haven't measured the false-positive rate of the code scan yet.

Roadmap

What is shipped, what is being built, and what doesn't exist yet.

  1. Shipped

    Foundation

    Nine prompts, validator, 50-record dataset, HTML report template and buyer ZIP.

  2. Shipped

    Local scanner extension

    Free Chrome extension runs axe on the active tab and exports findings and manual-review items as JSON.

  3. In progress

    Command-line scanner (site, sign-in, code to bug sheet to draft)

    wcag-toolkit v0.1: page, site and signed-in scans, a code scan, a bug sheet and a capped VPAT draft. Not released.

  4. Planned

    Guided VPAT workflow and Word export

    One step from scan to draft, report front matter saying what was scanned and how, reviewed flow files so a scan can click and type safely, AI-proposed ratings a person reviews and signs off row by row, and .docx export in the VPAT 2.5 layout.
