Take · T-04
An accessibility report nobody can find is a liability with a cover page.

I built VPAT Vault to make creating a VPAT simple enough that more websites can publish one. It combines a local Chrome scanner with a prompt toolkit and HTML template, so evidence moves into the report instead of ending up in a separate silo.

Why I made it

I wanted a scanning tool I would actually use alongside VPAT creation. The extension captures automated evidence where the work starts, while the prompts and template turn that evidence into a reviewable report. I exercised the workflow with my harness so the pieces stay connected from scan to draft.

The current release includes nine prompts, a dependency-free validator, a 50-record reference dataset, a report template, and a free Manifest V3 Chrome extension that runs axe locally and exports scan evidence. The roadmap is to connect multi-page scan sessions, evidence review, and report generation into one publishable workflow.

Roadmap

A practical path from a working evidence capture tool to a complete VPAT workflow.

  1. Shipped

    Foundation

    Nine prompts, validator, 50-record dataset, and HTML report template.

  2. Shipped

    Local scanner

    Free Chrome extension runs axe on the active tab and exports canonical scan JSON.

  3. Next

    Scan sessions

    Capture evidence across multiple pages while keeping findings connected to the report.

  4. Planned

    Launch workflow

    Review evidence, draft rows, run QA, and publish a VPAT from one guided flow.
